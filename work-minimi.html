A product and growth internship story about finding the market that actually wanted the product.

Minimi is private, on-device memory for Claude. It remembers your work context so you stop re-explaining yourself across tabs, tools and meetings.

Before the shift, it was positioned as a project-management or context tool. That looked clean on paper, but it missed the actual job-to-be-done for the people who were adopting it fastest.

Before the pivot, the product was stuck in the middle: more interest than traction, but not enough repeat usage after day 1. The launch window was short and the wrong ICP was burning runway.

Why it mattered: the team had a narrow pre-launch window and no time to keep optimizing for the wrong buyer. We needed clarity, not another feature.

I talked to 40+ users across founders, PMs, ops leads, and developers. The assumed ICP was “PMs managing projects.” The real pattern was very different: heavy Claude users losing context across tools every single day.

People didn't want a PM tool. They wanted Claude to already know what was on their screen and what they had been doing before. That changed the framing of the entire product.

“I don’t need another dashboard. I need a system that remembers my context so I don’t have to explain my work from scratch every time.”

Ops lead, US

“If it remembers what I’m looking at, it becomes useful immediately. If it asks me to set up projects first, it feels like work.”

Founder, India

Aha: the real pain was not project management — it was context loss, repeated explanation, and slower AI output.

01
Rebrand: from a work-tool-sounding name to Minimi, positioned around memory instead of management. The new name matched a use case people instantly understood.
02
Onboarding reset: stripped down setup, removed project configuration upfront, and changed the first interaction from “create workspaces” to “capture context fast.”
03
Feature shipped: an on-screen context layer powered by MCP so the product could understand what a user was working on, without friction.
04
Tradeoff: we intentionally dropped broader PM features that some existing users liked, because a sharper focus was the only way to win the real customer.

The first flow asked people to do labor before they saw value. The second made memory the value itself.

Attribution was shared: the ICP shift and onboarding fix drove activation; the onboarding and personal outreach drove the paid conversion; the new feature helped retention; the launch amplified reach.

The biggest unlock was not a better feature list; it was matching the real pain.
ICP shift + onboarding redesign improved activation more than any standalone feature could.
We learned to move earlier from interviews to product decisions, before shipping an architecture around the wrong problem.
